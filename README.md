# 薪算

Vue 3 + JavaScript + Vite 的工资、累计个税和五险一金测算工具。Node.js 仅在本地同步城市政策；部署到 GitHub Pages 后，浏览器用 sql.js 读取同站点 SQLite，计算不依赖后端。

只提供 **工资计算**、**数据同步** 两个页面。不收集姓名、公司、信用代码，不保存工资流水或计算参数。数据库初始为空，按需添加城市。

## 本地使用

需要 **Node.js 24 或以上版本**（使用内置 `node:sqlite`）。

```sh
npm install
npm run dev
```

打开 `http://127.0.0.1:5173`，进入“数据同步”，输入城市名称，例如 **杭州市**、**上海城区**，点击“同步此城市”。成功后返回“工资计算”。

- 页面由 `src/router/index.js` 中的路由表管理，地址分别为 `#/calculator`、`#/sync`，可直接打开、刷新及前进后退。计算页在切换时保留输入、结果和复制标记。
- 城市下拉框模糊匹配 SQLite `cities` 表中的已有名称，支持上下方向键、回车选择和 Escape 关闭。计算页只接受已有城市；同步页允许输入新城市。
- 新城市只有在查询、字段校验成功后才与政策一起写入同一个事务。城市不存在、网络异常或数据格式不正确时，不会新增 `cities` 记录。
- 月度明细的“税前工资”和“个人所得税”可分别复制，仅复制该月对应金额（两位小数，不含千分位和单位）。成功后金额变蓝并显示勾选；“重置复制标记”统一复原，新计算结果也会清除旧标记。汇总金额不提供复制按钮。
- 页面不展示外部服务名称、来源链接和原始备注/错误信息；内部同步接口、原始政策存储保持不变。

- `npm run dev`：同一个本地服务提供页面、数据库文件与同步接口，启动时自动初始化数据库。
- `npm run server`：仅启动接口服务，地址 `http://127.0.0.1:3001`。
- `npm run db:init`：创建空数据库，已有城市和政策保持不变。
- `npm run build`：生成静态站点到 `dist/`。
- `npm run preview`：预览静态产物；不提供同步接口。

服务只监听本机。端口冲突时可以用 `PORT` 环境变量更换端口，例如 PowerShell：

```powershell
$env:PORT = '5174'
npm run dev
```

进入同步页会连接本地服务；在线页面不尝试调用电脑的 localhost。页面刷新或切换不会终止服务端正在执行的同步任务，重新进入同步页会恢复进度查看。关闭 Node 进程会中断任务，已经成功的城市数据仍然保留。

## 发布到 GitHub Pages

1. 将项目放入 GitHub 仓库，提交 `package-lock.json` 和 **`public/data/policies.sqlite`**。
2. 仓库 Settings → Pages → Build and deployment → Source 选择 **GitHub Actions**。
3. 推送到 `main` / `master`，或手动运行 “Deploy GitHub Pages” 工作流。
4. 工作流安装依赖、构建并发布 `dist/`，无需在线运行 Node。

页面使用 hash 导航、相对资源路径；兼容用户根站点、仓库子路径和自定义域名，不必修改仓库名配置。WASM 随构建产物发布，不依赖 CDN。

以后每次在本地同步完成，只需提交并推送 `public/data/policies.sqlite`，工作流会重新发布。请等同步任务结束后再提交数据库。工具不会自动执行 Git commit 或 push。

```text
工资哥 API → 本地 Node 同步 → public/data/policies.sqlite
                                   ↓ Git push + Pages 发布
浏览器 ← 同源 SQLite 文件 ← GitHub Pages
  ↓ sql.js 查询政策
纯前端按月计算 → 当前页面显示（不写入、不持久保存工资）
```

GitHub Pages 上的数据库是公开静态文件。此项目只在其中存储城市政策，没有个人工资数据。

## 计算口径

- 金额用 `decimal.js` 做十进制乘除，月度累计使用整数分；社保、公积金分别按数据源的小数位与进位规则舍入，正确保留精度 `0`。
- 随机工资在固定月薪 ± 浮动金额之间按分生成。普通重算、切页、展开明细复用已经生成的浮动值；点击“重新生成浮动”，或变更起止日期/浮动幅度会重新抽取。刷新页面后不保留。
- 首尾月工资 = 浮动后的整月月薪 × 在职计薪天数 ÷ 当月全部计薪天数；完整月直接取整月月薪。计薪日包含工作日、调休补班日、法定带薪节日，排除一般周末和调休休息日；入离职当天均在计数范围内。
- 已收录 **2025、2026 年**全国节假日日历。其他年份的完整月份可直接按整月月薪计算；非整月会明确提示补充日历，不会错误地仅按周一至周五折算。日历维护位置：`src/domain/calendar.js`。
- 入职月默认在 15 日及之前入职缴整月，否则不缴；离职月默认缴整月。社保、公积金各自提供首末月覆盖开关。同月入离职只应用首月规则。这是用户确认的测算设置，不作为全国统一缴费规定。
- 社保、公积金分别配置基数：默认政策最低、固定月薪全额、自定义。个人和公司分别按各自政策上下限限制基数。“工资全额”使用输入的固定月薪，不随随机工资或首尾月折算变化。
- 养老、医疗、失业、生育、工伤、公积金分别显示个人与公司金额。生育已合并至医疗的政策不会重复缴费；工伤默认最低档；公积金采用最低的一组公司/个人比例；补充公积金不缴。
- 可自定义各项目个人/公司比例。源政策没有该缴费方时不可编辑；自定义公积金比例限定在 0–12%。基数仍按政策限制。
- 所有月份统一使用 SQLite 内最新政策，页面明确提示不会还原历史政策。
- 工资薪金个税按当前单位任职月份累计，包含入职当月零工资的月份；每月减除费用 5,000 元，每年 1 月重置累计。累计应纳税所得最低为 0，本期预扣税额最低为 0，不在工资表中自动退回此前预扣税额。
- 不考虑专项附加扣除、首次就业特殊减除规则、前单位收入以及年度汇算。
- 年终奖按指定年月发放一次，不含该月工资，也不按出勤折算；支持单独计税、并入综合所得，默认单独计税。已收录的单独计税政策截至 2027-12，之后会提示更新政策或切换计税方式。
- 若首尾月工资少于个人缴费，到手净额可为负数，明细提示需补足金额。

### 数据源特殊字段

同步保留原始响应和标准化政策。对于附加大病医疗、地区附加公积金、额外公积金免税上限等尚未确认计费/计税结构的政策，允许保存并查看，但计算明确报错，不将这些金额默认为零。普通上海、杭州样例的五险一金字段已核对。

接口返回多个版本时，依次按 `stratedAt`、`updatedAt`（缺失时使用 `createdAt`）倒序选择一条最新政策，并显示其名称，不提供额外政策方案选择。

## 同步接口

以下接口默认从本地页面同源调用，也可从本机脚本调用。POST 使用 `Content-Type: application/json`。

| 方法 | 路径 | 请求体 | 作用 |
| --- | --- | --- | --- |
| GET | `/api/health` | 无 | 检查本地服务 |
| POST | `/api/sync/city` | `{"city":"杭州市"}` | 添加/同步一个城市，返回 202 和任务状态 |
| POST | `/api/sync/all` | `{}` | 串行同步库内全部城市，返回 202 和任务状态 |
| GET | `/api/sync` | 无 | 查询当前/最近任务、逐城市结果和进度 |
| GET | `/data/policies.sqlite` | 无 | 下载已提交的 SQLite 数据库 |

每次第三方请求结束后至少间隔 1 秒，跨任务也共用冷却时间。运行中的任务不能重复启动（HTTP 409）。单城市失败保留旧政策并继续其他城市；HTTP 403/429 时停止后续请求，显示跳过状态，避免持续触发限制。第三方请求超时为 30 秒，不自动重试。

使用的第三方接口：

```text
GET https://payroll.gongzige.com/policy/api/portal/get_by_city/{编码后的城市名称}/{当前毫秒时间戳}
```

## 数据库与模块

`cities` 保存城市名称、创建时间、最近成功同步时间和错误；`policies` 以城市名称关联，保存源政策 ID、名称、生效/更新时间、标准化 JSON 和原始响应 JSON。每个城市只保留当前政策。所有写入采用参数化 SQL，更新政策与同步时间在同一事务完成。DELETE 日志模式保证完成同步后只需提交一个 SQLite 文件。

```text
server/database.js            SQLite 表结构、事务与仓储
server/source.js              第三方请求与字母字段映射
server/sync.js                单任务串行同步、节流与进度
server/index.js               本机 HTTP 接口和 Vite 开发服务
src/services/policies.js      浏览器加载与查询 SQLite
src/services/sync-api.js      本地接口调用与异常处理
src/router/index.js           页面路由表与导航元数据
src/services/clipboard.js     剪贴板写入与兼容处理
src/composables/useAmountCopy.js 按月份、字段管理复制状态
src/domain/calendar.js        计薪日历与首尾月计薪天数
src/domain/money.js           十进制金额和舍入
src/domain/tax.js             累计工资税、年终奖税
src/domain/payroll.js         纯前端工资计算
src/components/              表单、城市搜索下拉、金额复制、政策查看、月度结果、同步页
public/data/policies.sqlite   需要提交到 Git 的政策数据库
```

政策字段映射已经与数据源公开政策页面核对：

| 项目 | 公司基数下/上限、比例 | 个人基数下/上限、比例 |
| --- | --- | --- |
| 养老 | G / H / K | I / J / L |
| 医疗 | M / N / Q | O / P / R |
| 生育 | AA / AB / AC | 无 |
| 失业 | AD / AE / AH | AF / AG / AI |
| 工伤 | AJ / AK / AL | 无 |
| 公积金 | AQ / AR / AS 中的公司比例 | AQ / AR / AS 中的个人比例 |

社保精度/舍入：`spAccuracy` / `spRoundMode`；公积金：`pfAccuracy` / `pfRoundMode`。模式 1 四舍五入、2 向上取整、3 向下取整、4 截断。
